A small, honest ritual for a repository that would otherwise sit still.

Green Graph Garden is a GitHub Action that touches this repo on a timer — refreshing a log, a status file, and this README — the way you might water a plant on your desk. It's decorative automation, built and labeled as exactly that.

What it actually does

On a schedule, a small Node script and a small Python script run inside a GitHub Actions workflow. They rewrite a status file and a short growth report in the README, then commit that change. There's no task list, no real work log — it's a scheduled write, dressed up in a garden theme because that's more pleasant to look at than a cron job.

It exists as a bit of fun around GitHub automation, not as a record of actual coding activity — the sections below say that plainly, on purpose.

How it runs

01

A schedule fires

The workflow in .github/workflows/daily-commit.yml runs on a cron trigger, or on demand.

02

Two scripts update local files

scripts/daily-green.js and scripts/generate_activity.py rewrite log.txt, data/green-status.json, and activity.json.

03

The README is refreshed

A short "today's growth report" section is regenerated with new placeholder mood and streak text.

04

One commit, pushed by the bot

Authored as Green Graph Bot, so it's clearly attributed to automation, not a person.

Plain-language note

This isn't a coding-activity signal

A GitHub contribution graph is meant to show real work. This project generates commits on a timer, so any streak or count it produces reflects the schedule, not effort — it shouldn't be read by anyone (including future-you) as evidence of actual development activity. Treat it as what it is: a small automated repo ritual, not a résumé line.
